## Context

Navbar bergetar saat scroll kontinu di sekitar posisi ~70px — tepat di ambang state-flip `navbar-scrolled` (`maxScroll = 4.5 × rootFontSize = 72px` di `tint-navbar.js`). Refactor `getNavbarShrink()` sebelumnya TIDAK menargetkan getaran ini (perilaku-preserving), jadi belum ter-fix. Tiga kandidat penyebab sudah teridentifikasi dan harus didiagnosa dulu sebelum fix, karena oboknya berbeda:

1. **Flip-flop ambang tanpa hysteresis** — `scrolled = y > maxScroll` tanpa zona mati; osilasi posisi scroll di sekitar 72px membuat kelas flip berulang dan tiap flip memainkan transisi tinggi 0.35s (`transition: all` di style.css ±2797).
2. **Mismatch kompensasi 14px** — section ditarik `margin-top: calc(-1 * var(--pf-navbar-h))` tetap 72px (style.css:234-235) walau navbar scrolled tinggal ~58px; transisi tinggi menimbulkan geseran yang terlihat.
3. **Layout thrash** — `applySplit` membaca rect 15 permukaan dan menulis style bergantian dalam satu loop per frame selama transisi tinggi berjalan.

## Langkah 1 — Didiagnosa pasti (bukan tebakan)

Karena event scroll fisik tidak di-dispatch di environment otomatis (terbukti: counter event = 0 walau halaman bergulir), diagnosis memakai **simulasi event scroll sintetis**: `window.dispatchEvent(new Event("scroll"))` setelah `window.scrollTo` — handler jQuery `$(window).on("scroll")` di `tint-navbar.js` menerima event sintetis sama seperti asli.

Prosedur di browser (localhost:8000, tab IAB):
- Instrumentasi: tiap ~30ms catat `scrollY`, `navH` (getBoundingClientRect), `classList.contains('navbar-scrolled')`, `--pf-split-y` capsule, `heroTop`.
- Skenario A: scroll berhenti TEPAT di y=71-73, dispatch event, tunggu 1s — lihat apakah state flip bolak-balik (kandidat 1).
- Skenario B: dispatch event di y=80 (scrolled), tunggu transisi selesai 500ms, ukur pergeseran `heroTop` vs `navH` (kandidat 2).
- Skenario C: selama transisi 0.35s berjalan, hitung jumlah penulisan `--pf-split-y` per frame (kandidat 3).

## Langkah 2 — Fix sesuai temuan

- **Jika kandidat 1 (paling mungkin)**: tambah hysteresis di `updateNavbarState()` (tint-navbar.js): menyala saat `y > maxScroll`, mati saat `y < maxScroll - 16` (margin 16px ≈ selisih tinggi 14px + buffer). State hanya bisa flip sekali per arah scroll, tidak bolak-balik di ambang.
- **Jika kandidat 2**: buat kompensasi section state-aware — `--pf-navbar-h` di-update JS mengikuti tinggi navbar terukur, ATAU matikan transisi `padding` navbar saat `data-scrolling` aktif (susutnya instan seperti warna section, sehingga tak ada periode geseran 14px).
- **Jika kandidat 3**: pisahkan `applySplit` jadi dua pass (baca semua rect dulu, baru tulis semua style) supaya tidak thrash.

## File yang disentuh

- `public/js/tint-navbar.js` — `updateNavbarState()` (hysteresis) dan/atau `applySplit()` (dua-pass), tergantung temuan.
- `public/css/style.css` — hanya jika kandidat 2 (transisi padding saat `data-scrolling`).
- Tidak menyentuh `navbar-shrink.js` / `custom.js` / `vertical-nav.js` (hasil refactor tetap utuh).

## Verifikasi

1. Skenario A-C diulang setelah fix: state `navbar-scrolled` harus flip PERSIS sekali per arah lintasan scroll; tidak ada osilasi `navH`.
2. Uji regresi fungsional (sudah ada prosedurnya dari sesi kemarin): `getNavbarShrink()` = 14 di top / 0 di scrolled; klik link nav dari bawah → section mendarat offset 0px; 0 error konsol.
3. Stress test: 20x dispatch scroll event bolak-balik di zona y=55-90 → jumlah flip class ≤ jumlah perubahan arah lintasan (tidak lebih).
